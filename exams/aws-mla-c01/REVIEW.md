# MLA-C01 問題のレビュー手順

問題の形式と文体のルールは同じフォルダの [`BRIEF.md`](BRIEF.md) にある。先に読む。問題は questions/ の下にある。

## 見ること

1. 正解が本当に正しいか。決め手の事実を AWS 公式ドキュメントで確かめる(`mcp__plugin_aws-core_aws-mcp__aws___search_documentation` を ToolSearch の `select:` で読み込む。使えなければ `mcp__plugin_aws-agents_awsknowledge__aws___search_documentation`)。
2. 不正解の選択肢が本当に不正解か。問題文の要件の読み方によっては正解にもなる選択肢(正解が2つ立つ)を探す。これが一番多い不具合。エンドポイントの種類、アルゴリズム、評価指標は、要件の語句(ペイロードの大きさ、処理時間、断続的なトラフィック、クラスの不均衡など)で1つに絞れているかを見る。
3. 並べ替えは、別の順番でも成り立たないか。内容一致は、別の組み合わせでも成り立つプロンプトがないか。
4. 範囲が C01 に収まっているか。RAG、ナレッジベース、エージェントなど C02 で足された内容を問うていないか。
5. 2026年11月時点の仕様か。新規受付を終えたサービス(Amazon Forecast)や提供を終えたサービス(Lookout for Vision、Lookout for Equipment)を正解にしていないか。保守モードに入った SageMaker AI の機能(Clarify、Model Monitor、Ground Truth、Debugger、A2I)を正解にした問題は、解説にそのことが1文あるか。名称(Amazon SageMaker AI)が BRIEF.md のとおりか。
6. 解説と optionNotes が正解と矛盾していないか。answer の添字が解説の内容と合っているか。
7. refs の URL が問題の内容と対応しているか(全部は開かなくてよい。怪しいものだけ確かめる)。
8. 文体: 太字、ダッシュ(— ― や「 - 」での区切り。公式のページタイトルに含まれるものは可)、「することができ」「活用」、だ・である調が混じっていないか。

## 直し方

- 見つけた不具合はそのファイルを直接直す。正解を変える、選択肢を書き換えて正解が1つに決まるようにする、解説を直す、など。直すときも裏を取る。
- 直せない(問題の前提ごと成り立たない)ものは、同じタスクで別の問題に差し替える。ID は変えない。
- 直したら `python3 build.py aws-mla-c01` をリポジトリの直下で実行し、NG が出ないことを確かめる(dist/ が書き換わるのは構わない)。
- 担当外のファイルは触らない。git のコミットはしない。
