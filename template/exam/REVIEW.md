# ○○試験 問題のレビュー手順

<!--
問題を作ったのとは別のエージェントに読ませるファイル。○○ と <...> を自分の試験に合わせて書き換える。
-->

問題の形式と文体のルールは同じフォルダの [`BRIEF.md`](BRIEF.md) にある。先に読む。問題は questions/ の下にある。

## 見ること

1. 正解が本当に正しいか。決め手の事実を公式の資料で確かめる。<裏取りに使うツールがあれば書く>
2. 不正解の選択肢が本当に不正解か。問題文の要件の読み方によっては正解にもなる選択肢(正解が2つ立つ)を探す。これが一番多い不具合。
3. 今の仕様や制度に合っているか。<提供が終わった製品、名前が変わったもの、改正された制度など、この試験で古くなりやすい点を書く>
4. 解説と optionNotes が正解と矛盾していないか。answer の添字が解説の内容と合っているか。
5. refs の URL が問題の内容と対応しているか(全部開かなくてよい。怪しいものだけ確かめる)。
6. 文体が [`BRIEF.md`](BRIEF.md) の決まりに合っているか。

## 直し方

- 見つけた不具合はそのファイルを直接直す。正解を変える、選択肢を書き換えて正解が1つに決まるようにする、解説を直す、など。直すときも裏を取る。
- 直せない(問題の前提ごと成り立たない)ものは、同じタスクで別の問題に差し替える。ID は変えない。
- 直したら `python3 build.py <試験ID>` をリポジトリの直下で実行し、NG が出ないことを確かめる。
- 担当外のファイルは触らない。git のコミットはしない。

## 完了報告

- ステータス
- 直した問題: ID ごとに、何が問題で、どう直したか、根拠の URL
- 問題なしと判断したが際どいもの
- 確かめきれなかったもの
