# 自分の試験の問題集を作る

受けたい資格試験の模擬問題集を、Claude に頼んで作る手順。作者は AWS Certified Security - Specialty の120問を同じ流れで作った。完成形は [`exams/aws-scs-c03/`](../exams/aws-scs-c03/) にある。

手を動かすのはほぼ Claude で、人は試験名を伝え、出てきた結果を確かめる。

```text
○○試験の問題集を作って
```

これだけで始まる。Claude は下の段を順に進め、段の終わりごとに確かめてほしい点を伝えて止まる。確かめたら「進めて」と返せばよい。途中からやり直したいときや、1段だけ頼みたいときは、各段の「頼む文」を送る。

試験IDは Claude が試験名から決めて伝えてくる(SCS-C03 なら `aws-scs-c03`)。下の説明では仮に `my-exam` と書いている。

## 用意するもの

- このリポジトリを clone したフォルダで動く Claude。ターミナルの Claude Code でも、Claude デスクトップ版の Claude Code でもよい。
- Python 3。ビルドは標準ライブラリだけで動く。

選択肢の数は、単一選択が4つ、複数選択が5つに決まっている。5択の単一選択や6択の問題は今のページでは出せない。

Claude はリポジトリ直下の [`CLAUDE.md`](../CLAUDE.md) を読み、問題集をどう作るかを知った状態で始まる。

## 1. 出題範囲を集めさせる

頼む文。

```text
○○試験の問題集を作って
```

Claude は試験IDを決めて雛形を `exams/<試験ID>/` に写し、公式の試験ガイドを読んで [`exam.json`](../template/exam/exam.json) を全部埋める。ここが問題集の骨組みになる。

| 項目 | 書くこと | 使われる所 |
|---|---|---|
| `id` | 試験ID。フォルダ名と同じにする | ビルドの出力先 `dist/<id>/` |
| `title` `brand` `tag` | 問題集の名前と、横に付ける短い札(版や年度) | ブラウザのタブ、画面左上 |
| `examName` | 試験の正式名称 | チャットの Claude と類題作りへの指示 |
| `examSize` | 本番の問題数 | 模擬試験の問題数 |
| `domains` | 分野の番号、名前、配点(%)、細目 | 分野ごとの練習と、模擬試験の配分 |
| `tutorNote` | チャットの Claude に足す指示 | チャット |
| `genNote` | 類題を作らせるときに足す指示 | 類題作り |
| `searchChip` | よく探しそうな論点の例(「○○の問題を探して」) | チャット欄の質問の候補 |
| `guide` `artifact` | 公式ガイドと公開先の URL | 記録だけで、ページには出ない |

人が確かめるのは、分野と配点が公式ガイドと合っているか。模擬試験は配点の比率で分野ごとの問題数を決めるので、配点がずれると模擬試験の配分もずれる。分野ごとの配点が公表されていない試験は、出題数の比率がわかればそれを、わからなければ均等に書く。試験ガイドが PDF でしか無い、ログインが要る、といった場合は、自分で取ってきて Claude に渡す。

情報処理技術者試験のように分野と細目の2階層が無い試験は、大分類を分野、中分類を細目として当てはめる。

## 2. 問題の作り方を決めさせる

頼む文。

```text
BRIEF.md と REVIEW.md を、この試験に合わせて書いて。
一次情報の節には、裏取りに使う公式の資料と、古い知識で書くと間違えやすい点を挙げて。
```

[`BRIEF.md`](../template/exam/BRIEF.md) は問題を作る Claude に読ませるルール、[`REVIEW.md`](../template/exam/REVIEW.md) は見直す Claude に読ませる手順。

人が確かめるのは「一次情報」の節。最近の制度の改正や名前が変わった製品など、知っている落とし穴があれば足すよう頼む。Claude は放っておくと記憶で書き、数年前の仕様を正解にすることがある。

## 3. 問題を作らせる

頼む文。

```text
BRIEF.md に従って、分野ごとにサブエージェントを分けて問題を作って。
全体で120問、分野ごとの数は配点に合わせて。
```

Claude は分野ごとに `questions/d1.json` のようなファイルを書き、雛形に入っていた見本の [`sample.json`](../template/exam/questions/sample.json) を消す。SCS-C03 は6分野で、1ファイル17〜23問になっている。

問題数は、各分野で「`examSize` × 配点」以上あると、模擬試験が本番と同じ長さになる。足りない分野があると、その分だけ模擬試験が短くなる。

## 4. 別の Claude に見直させる

頼む文。

```text
問題を作ったのとは別のサブエージェントに、REVIEW.md の手順で全問を見直させて。
直した問題と、確かめきれなかったものを一覧にして。
```

作った Claude に見直させると、自分の書いたものを正しいと思い込みやすい。必ず別のサブエージェントにする。

見直しで一番多く見つかるのは、要件の読み方によっては正解が2つ立つ問題。人は返ってきた一覧のうち「確かめきれなかったもの」を読み、怪しければもう一度裏を取らせるか、問題を差し替えさせる。

## 5. ビルドさせる

頼む文。

```text
ビルドして、件数と正解位置の分布を見せて。
```

[`build.py`](../build.py) は、形式の誤りがあると `NG` を出して止まる。選択肢の数、正解の添字、`exam.json` に無い細目、数値になっていない `domain`、ID の重複、フォルダ名と違う `id` が対象。止まったら Claude に直させる。最後に `書き出し:` の行が出れば成功。

`注意` の行は止まらない警告で、配点の合計が100でない、模擬試験に足りない分野がある、といったときに出る。単一選択の正解位置が A ばかりのように偏っていたら、散らすよう頼む。

できた `dist/my-exam/index.html` はブラウザでそのまま開ける。このままでも解けるが、回答は保存されず、Claude のチャットも使えない。

## 6. Artifact として公開させる

頼む文。

```text
Artifact として公開して。
```

Claude は公開した URL を `exam.json` の `artifact` に書き留める。Artifact として公開すると、回答履歴が claude.ai のアカウントに保存され、どの端末で開いても続きから解ける。解説の横で Claude に質問したり、類題を作らせたりもできる。チャットと類題作りは、開いた人の claude.ai の使用量を使う。

公開には Artifact を公開できる Claude が要る。作者は Claude デスクトップ版の Claude Code で公開している。ターミナルの Claude Code では公開のツールが無いことがあった。その場合は作るところまでをターミナルでやり、公開だけデスクトップ版に頼めばよい。

## 7. 直して公開し直させる

解いていて間違いを見つけたら、問題IDと気づいたことを添えて頼む。

```text
D2-014 は、選択肢 B も正解に読める。直して公開し直して。
```

Claude は裏を取って直し、ビルドして、`exam.json` に書いた URL の Artifact を更新する。同じ URL の Artifact を更新しないと、別の Artifact が新しくできる。回答履歴はその Artifact の DB に保存されているので、別の Artifact になると履歴が引き継がれない。

## 構成図を付けるとき

`exams/my-exam/diagrams/<問題ID>.svg` を置くと、ビルドが拾ってその問題の解説に載せる。問題IDに当たらない SVG は載せない。

読み上げ用の説明は、同じ名前の `.yaml` の先頭のコメントから取る。draw.io などで描いた SVG なら、`.yaml` には次の行だけ置けばよい。

```yaml
# D1-005: 検出した脅威を通知するまでの流れ
# 補った部品: ALB、ECS
```

1行目は、最初の `:` より後ろが説明になる。2行目は問題文に無い部品を図に足したときだけ書き、図の下に小さく出る。

図があるときは、公開するときに `dist/my-exam/diagrams/` の SVG も添付ファイルとして一緒に載せるよう Claude に頼む。
